## 一、專案主題

**Monti 發球教練（Serve Coach）：以國產大語言模型與影像模型打造的桌球發球即時 AI 指導服務**

以一支手機取代需要專用器材與國外雲端的發球分析，為台灣基層桌球（國中小校隊、社區球館、社會人學習者）提供「每一球都有回饋」的中文即時教練，並將推論能力延伸為可跨運動、跨場域複製的「動作量測 → 中文指導」通用服務模板。

## 三、使用模型需求

平台預設開源模型中，本案規劃**同時串接影像模型與大語言模型**，形成一條完整的「看見 → 量測 → 說明 → 處方」推論鏈。

### 3-1 影像模型：**YOLO**

| 項目 | 內容 |
|---|---|
| 串接模型 | **YOLO**（平台預設影像模型） |
| 推論對象 | 每一次發球被偵測後擷取之關鍵影格（每球約 30 張，240 fps 裁切畫面） |
| 偵測類別 | 球（ball）、球拍（racket）、球網與網柱（net）、球桌邊線與桌角（table）、發球者（player）、觸球瞬間（contact frame） |
| 呼叫時機 | **非即時串流**。發球結束後的 2～3 秒空檔（選手正在撿球）批次送出該球的影格，屬「突發、小批量、事後」型推論，與推論 API 的計費與延遲特性高度相符 |

**為什麼需要平台的 YOLO（這是本案最關鍵的技術缺口）**

目前原型的球體偵測，是以「背景模型 + 移動像素 + 圓形團塊 + 軌跡連結」的傳統電腦視覺手法，在手機上自行實作（`core/ServeTracker.kt`）。此法可行，但代價是三個已被實測證實的限制：

1. **必須使用手工標記的球。** 現行旋轉量測需在球上塗黑半球、畫一條線與一個點，才能從畫面解出三維旋轉。這對一般使用者是極高的進入門檻，也是本服務無法直接商品化的主因。
2. **硬編規則在真實球館會失效。** 實測已記錄：藍色球桌上迎面飛行的球無法被追蹤；擊球瞬間球與球拍團塊合併，導致量測到球拍而非球；選手走過鏡頭被誤判為發球（某次場測 34 個擷取中約 30 個是人體）。這些都靠不斷增補啟發式規則勉強排除，不具備可擴充性。
3. **看不見球拍、球網與落點。** 因此無法判定發球合法性（拋球 16 公分、掌心攤平、球台端線後）、過網高度與第二落點——而這些正是初學者最需要、教練最常糾正的項目。

**平台 YOLO 正好解決這三點**：以學習式偵測器取代手工規則，可偵測**未經標記的一般白球/橘球**於雜亂球館背景中的位置，並同步產出球拍、球網、球桌與人體的邊界框。這讓服務從「需要特製球的實驗工具」變成「任何人拿起手機就能用的產品」，是本案能否商品化的分水嶺。手機端不需要、也無法以 240 fps 執行大型偵測器——但本案**也不需要**，每球僅需事後推論約 30 張影格，正是推論 API 的最佳使用情境。

### 3-2 大語言模型：**TAIDE**（主要）／**福爾摩沙大模型 FFM**（次要）／**Meta Llama**（對照）

| 項目 | 內容 |
|---|---|
| 串接模型 | **TAIDE**（主）、**FFM**（次）、**Meta Llama**（A/B 對照評測用） |
| 推論輸入 | 每球之結構化量測數值：旋轉速率（rev/s）、旋轉軸三分量（下旋／側旋／陀螺旋）、出球速度、拋球速度、旋速比（接觸厚薄）、摩擦利用率、過網高度、落點、合法性旗標、以及該名學員近期趨勢 |
| 推論輸出 | ①單球一句中文語音提示（≤ 20 字）②單次課後中文總結與下一步練習處方 ③週期進步敘事報告（學員／家長／教練三種語氣） |

**為什麼選用 TAIDE／FFM（國產繁體中文模型）而非國外模型**

1. **語言與術語是本案的功能本體，不是包裝。** 教學提示必須講出台灣球館真正在用的話：「摩擦薄一點」「拍面再立一點」「拋球太前面了」「這球是側下不是純下旋」。這些詞彙與語感，英文模型翻譯後會變成教科書語言，初學的國中生聽不懂也不會照做。TAIDE 以繁體中文及台灣語料為訓練基礎，是此需求的最合適選擇。本案現行原型的回饋只有 **thick / good / slip / slow 四種固定英文分類句**——這正是必須用 LLM 取代的部分。
2. **使用者多為未成年人，訓練影像不應出境。** 服務對象大量是國中小校隊學生，影片與姿態資料屬高敏感個資。串接國內算力平台的國產模型，資料全程留在境內，是面對學校與家長時唯一能說得過去的架構。
3. **成本結構決定商業模式是否成立。** 本服務目標定價為學生可負擔的月費等級，每球都要呼叫一次 LLM。使用國產模型的在地推論成本，是本產品能以 B2C 訂閱落地的前提。
4. **本案原規劃使用國外 API（Google Gemini），本次申請即是將其替換為國產模型的具體行動**（見專案文件 `PLAN.md`、`docs/later-forehand-plan.md` 之原始規劃）。這是一個真實、可驗證的「國產大模型取代國外 API」落地案例，而非事後補述。

### 3-3 法規遵循聲明

本案**不使用任何源自中國或中資之開源模型（如 DeepSeek 等）或介接工具（API、MCP 等）**，亦不以任何方式將本平台串接至中、港、澳之遠端 IP 位址，完全遵守申請須知「柒、二、(一)」之使用規範。現行原型所使用之第三方元件為 MediaPipe（Google，Apache-2.0）與 mp4box.js（GPAC，BSD-3-Clause），授權清楚且無前述疑慮。

## 四、專案重要性

### 4-1 需解決的問題

**問題一：發球的好壞，肉眼看不見。**

桌球發球的旋轉速率在每秒 14～63 轉（約 840～3,800 RPM），球體直徑僅 40 公厘。人眼看不見，一般手機 30 fps 的錄影也看不見。於是初學者最常見、也最令人挫折的狀況是：**「我知道這球不好，但我不知道哪裡不好。」** 教練能說「你要摩擦薄一點」，但無法量化地告訴學生「你這球旋速比 0.72，是推出去的不是摩擦出去的」。發球是桌球**唯一完全由自己掌控**的技術，也因此是初學者投報率最高的練習項目——偏偏它的回饋品質最差。

**問題二：基層教學的師生比，讓「每一球都有回饋」在結構上不可能。**

台灣基層桌球的真實現場：一位教練帶 20～30 名學員，一堂課兩小時。即使教練全程不休息，平均分配到每位學員身上的注意力不到 4 分鐘；一位學員一堂課發 50～100 球，真正被看到並得到回饋的不到 5 球，**超過 90% 的練習是沒有回饋的重複**。沒有回饋的重複不會帶來進步，只會把錯誤動作練得更牢固。這不是教練不盡責，而是人力的物理上限。

**問題三：現有技術方案不適用於台灣基層。**

目前國際上唯一的同類產品是德國 ESN 的 **Spinsight**（2025 年 2 月推出）：iPhone 13 以上、需掛網柱支架、**需使用專用標記球**、影像送至其雲端處理、月費約 10 歐元、**無中文介面、僅回報數值不提供教學處方**。對台灣的國中小校隊而言，它同時卡在器材門檻、語言門檻、價格門檻與資料出境疑慮四道關卡。台灣目前沒有任何本土方案。

**問題四：我們已經證明「測得準」，但卡在「講不出人話」與「要特製球」。**

本團隊已完成可運作的 Android 原型（詳見第五節），旋轉量測與人工逐格計數的誤差在 5% 以內、手機端與電腦端讀數一致到 0.1 rev/s。但現況是：
- 必須使用**手工塗黑並畫線的標記球**，一般使用者無法使用；
- 回饋只有 **thick / good / slip / slow 四種固定分類**，沒有中文、沒有個人化、沒有「下一步該練什麼」。

**這兩道缺口，正好分別對應平台的 YOLO 與 TAIDE／FFM。** 本案申請的不是「從零開始做一個 AI 專案」，而是**把一個已經驗證過核心演算法的系統，接上它唯一缺少的兩塊推論能力，推進到可商品化**。這是本案與多數概念型申請案最根本的差異。

### 4-2 預計選用的模型原因

（完整論述見第三節 3-1、3-2，摘要如下）

| 模型 | 選用原因 |
|---|---|
| **YOLO** | 取代手工規則式球體偵測，使服務**不再需要特製標記球**；同步偵測球拍、球網、球桌與人體，才能判定發球合法性、過網高度與落點。這是本案從實驗工具走向可販售產品的唯一路徑。推論量為每球約 30 張影格之事後批次處理，與推論 API 特性完全相符。 |
| **TAIDE** | 教學語言即功能本體。需要的是台灣球館真實使用的繁體中文術語與語感，而非翻譯腔。對象多為未成年學生，影像與姿態資料不應出境。國內推論成本是 B2C 訂閱定價成立的前提。 |
| **FFM** | 作為長文脈（週期報告、跨課程趨勢敘事）之次要模型與備援，確保單一模型異常時服務不中斷。 |
| **Meta Llama** | 作為 A/B 對照組，量化驗證國產模型在本場域之表現，並將比較結果納入結案報告，回饋予平台與產業。 |

### 4-3 對臺灣產業的價值

1. **補上台灣運動科技最缺的那一塊。** 台灣在運動科技擁有全球少見的雙重優勢：手機與感測硬體製造能量，加上桌球、羽球高度普及的基層場域。缺的是**把 AI 推論落到教學現場的本土服務案例**。本案提供一個完整、可被引用、可被複製的垂直場域模板。
2. **建立國產大模型的真實垂直落地案例。** TAIDE／FFM 目前多見於通用問答與文件處理的示範。本案是一個**消費端、高頻、即時、有明確付費意願**的應用：每一球呼叫一次，一堂課數千次。這類高頻垂直應用的實證數據（延遲分布、成本結構、繁中術語表現、與國外模型的 A/B 比較），對國產模型生態的價值，遠高於再一個聊天機器人。
3. **產出台灣自有的桌球視覺資料集。** 本案將建立並開源**台灣球館實景的桌球發球標註資料集**（球、球拍、球網、球桌、觸球影格），這是目前華語圈不存在的公共資產，可供後續研究者、學界與其他業者直接使用。
4. **降低體育科技的進入門檻。** 本案開源推論串接範例程式碼後，其他運動項目（羽球發球、網球發球、棒球投球）的團隊可直接沿用「手機高速攝影 → 平台 YOLO → 平台 LLM → 中文語音指導」這條管線。

### 4-4 帶動產業數位轉型

本案推動的是**基層體育教學單位從「經驗傳承」到「資料驅動」的轉型**：

| 面向 | 轉型前 | 轉型後 |
|---|---|---|
| 練習回饋 | 教練口頭、主觀、每人每堂不到 5 球 | 每球量化回饋，一堂課 50～100 球全覆蓋 |
| 進步追蹤 | 憑教練印象與比賽成績 | 旋轉速率、穩定度、合法率的時間序列 |
| 教學決策 | 整班統一課表 | 依個人弱項自動產生差異化練習處方 |
| 親師溝通 | 「他最近有進步」 | 中文進步報告，含具體數據與下階段目標 |
| 教練培訓 | 師徒口傳 | 量化指標 + AI 講評，新手教練可快速校準判斷 |

對球館經營者而言，這同時是**服務差異化與營收工具**：導入後可開設「AI 發球診斷課」，並以進步報告提升續課率。

### 5-1 場域應用情境

**情境 A：國中小桌球校隊的團體練習課（主要情境）**

放學後的體育館，一位教練、24 名隊員、6 張球桌。每張球桌旁架一支手機（側面、與球桌同高、鏡頭略高於桌面），學員戴上單耳藍牙耳機自主練習發球。

- 學員發球 → 手機以 240 fps 持續錄影並即時判定「這是一次發球」（非撿球、非拋球、非路人走過）
- 該球的關鍵影格送至平台 **YOLO**，取得球、球拍、球網、球桌與人體位置
- 本地物理引擎據此計算旋轉速率與旋轉軸、出球速度、旋速比、摩擦利用率、過網高度、落點、拋球合法性
- 量測結果送至平台 **TAIDE**，回傳一句中文提示，**在學員撿下一顆球的 2～3 秒內**由耳機念出：
  - 「這球是推出去的，拍面再立一點，往下薄薄地切。」
  - 「下旋夠了，但過網太高，球拋低一點。」
  - 「拋球沒有到 16 公分，裁判會判重發。」
- 一堂課結束，每位學員收到中文課後總結與三項指定練習；教練在平板上看到全隊 24 人的弱項分布，決定下一堂課的團體重點。

**情境 B：社區球館的成人自主練習**

球館設置「AI 發球練習台」，使用者掃碼開始，以 B2C 訂閱或單次計次使用。這是本案主要的付費場景。

**情境 C：個人在家或在任何球桌邊自主練習**

純手機方案，不需任何額外器材（**這正是需要平台 YOLO 取消標記球需求的原因**）。

### 5-2 預期成效表現

| 指標 | 現況（原型實測） | 本案導入推論服務後目標 |
|---|---|---|
| 是否需要特製標記球 | **必須** 手工塗黑並畫線 | **不需要**，一般白球／橘球即可（平台 YOLO） |
| 每堂課每位學員獲得回饋的球數 | 教練人力：< 5 球 | **≥ 45 球**（50 球中有效辨識 ≥ 90%） |
| 發球偵測準確率 | 已標註 31 球全數偵測成功；但曾有場次 34 個擷取中約 30 個為人體誤觸發 | 發球召回率 ≥ 95%、誤觸發率 ≤ 5% |
| 旋轉量測誤差 | 與人工逐格計數誤差 ≤ 5%（4 球實測）；手機與電腦讀數差 ≤ 0.1 rev/s | 維持 ≤ 5%，並擴大至 ≥ 300 球之標註驗證集 |
| 回饋語言與內容 | **英文 4 類固定分類句** | **繁體中文個人化語句**，教練盲測可用率 ≥ 80% |
| 單球回饋延遲 | 量測 2～13 秒（視擷取大小） | **端到端 ≤ 3 秒**（落在撿球空檔內） |
| 發球合法性判定 | **無此功能** | 拋球高度、拋球角度、過網高度判定，準確率 ≥ 85% |
| 課後處方 | **無此功能** | 每堂課自動產生中文總結與 3 項指定練習 |

### 5-3 為什麼這些情境需要「推論 API」而非端側模型

1. **時間特性相符**：桌球發球之間有 2～3 秒的自然空檔（撿球），推論不需要串流級即時性，完全容許一次網路往返。
2. **運算特性相符**：手機端已承擔 240 fps 的影像擷取與追蹤（實測可全幀擷取，13,074 影格中僅漏 2 格），但無力同時執行大型偵測器；而本案只需對每球約 30 張影格做事後推論——這是推論 API 的理想負載形狀。
3. **語言能力無法端側取得**：具備台灣桌球術語語感的繁中生成，端側小模型做不到。
4. **可持續改進**：Prompt 與偵測類別可在雲端迭代，使用者不需更新 App。

### 6-2 跨產業應用的做法

本案真正的可複製資產，不是「桌球」，而是**「手機高速攝影 → 平台影像模型取得物件位置 → 物理模型量測 → 平台大語言模型轉為母語指導」這條推論管線**。它的三個組件（偵測、量測、指導語言生成）之間介面清楚，更換量測模型即可移植。

| 延伸領域 | 做法 | 共用的部分 |
|---|---|---|
| **其他運動項目**（羽球發球、網球發球、棒球投球、高爾夫揮桿） | 更換物理模型與 YOLO 偵測類別，介面不變 | 高速攝影管線、動作偵測、LLM 指導語言層、語音回饋 |
| **體育科系術科教學與檢定** | 以量化指標輔助術科評分與學習歷程記錄 | 全部管線 + 報告生成 |
| **復健與運動傷害防護** | 以同一管線量測復健動作的完成度與代償，由 LLM 產生中文衛教指示 | 動作偵測、姿態分析、LLM 指導語言層 |
| **職業訓練與技能檢定**（如技職術科動作） | 高速動作的標準化量測與中文回饋 | 全部管線 |
| **製造業作業動作分析** | 以相同管線分析產線作業員動作一致性，LLM 產出中文改善建議 | 偵測 + 動作量測 + LLM 建議層 |

**具體的跨產業推進作法**：
1. 將推論串接層抽離為獨立的**開源 SDK**（「動作量測 → 中文指導」通用模組），任何團隊可替換自己的量測邏輯。
2. 公開完整的技術白皮書與繁中教學文章，降低其他業者的複製成本。
3. 結案後以本案成果為基礎，主動接洽運動科技、復健醫材與智慧製造業者進行技術合作或授權。
